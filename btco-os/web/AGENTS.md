# Browser application release contract

Follow ../AGENTS.md when working in the canonical GitHub repository. GitHub web/ is authoritative; the Sites repository is a publication mirror, never an independent development branch.

Preserve owner-private access, the existing D1 database, shared revisions and recovery snapshots. No source deployment may replace stored inventory. Do not embed production source reports or credentials. Browser boot joins the authenticated workspace and preserves device differences; new users start empty.

Keep semantic browser versions in package metadata, cache imports, public/release.json, CHANGELOG.md and docs/releases/. Run tests, release checks, typecheck and production build. Use the current Sites workflow for packaging and publication, then verify the terminal deployment and its source mapping.

CDP remains the listing hub. Preserve exact master SKUs, source aliases, costs, sales and review exclusions. Vision proposes identities and saves review drafts outside inventory counts. Retain all archived Vision source fingerprints. Do not restore glasses support to the maintained iPhone app. Device compilation remains unverified without Mac/Xcode.

Keep at least 5% promotion in eBay evaluations. Active asks are not sold evidence. No purchases or marketplace writes. The existing CSV upload access control still applies; do not route blocked uploads through source or deployment. Authorized connector API observations use the dedicated inventory-sync contract.
