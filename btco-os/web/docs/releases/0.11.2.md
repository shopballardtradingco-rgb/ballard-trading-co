# Browser 0.11.2 — exact CDP identity protection

## Scope

Intake candidate lookup may normalize aliases, but the linked master SKU now copies the established identifier verbatim. New confirmed master identities retain their literal value. Shared saves reject replacement/removal of existing `source.cdpSku`, `source.cdpId` and `cdpLink.sku` values.

## Data

No data migration, live reconciliation, record deletion or physical-stock change. Existing legacy links remain readable; this release does not silently repair historical identities. The owner-private Site, database and recovery snapshots remain in place.

## Verification

Four assertions failed against the inspected 0.11.1 behavior, then passed after the fixes. The full 136-test browser suite passes, including real Worker/D1 persistence and complete-listing collection. Release fingerprints, typecheck and production build are required deployment gates. The Python operator utility is unchanged.

## Limitations

This prevents future identifier replacement; it is not a census proving all historical production mappings correct. A deliberate master-ID correction needs a separately reviewed migration with provenance. Actual iPhone compilation/camera use, real-card AI recognition and mobile/desktop visual acceptance remain unverified in this environment. See the canonical October 12 technical audit for the broader feature matrix and next releases.

## Rollback

Restore the previously saved Site version 17 if needed; do not replace D1 data. A source rollback removes these new write protections, so prefer a forward fix. Keep GitHub canonical and record the exact source/mirror/deployment mapping in the root release record.
