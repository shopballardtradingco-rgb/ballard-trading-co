# BTCo OS 0.9.0 — CDP-first intake and record linking

## Scope

Keep CDP as the listing hub. Replace Vision’s generated-SKU receipt form with shared intake drafts and explicit linking to an existing CDP record. Successful photo scans save a draft without increasing inventory; manual results and edits can be saved explicitly. Existing SKU/alias matches link the same record; genuinely new counterparts use the confirmed CDP master SKU. Add pending-draft navigation, CDP link details, attached reviewed evidence and CSV columns. Retain public PSA research and optional API setup.

## Data

No database migration, new storage array, backup-schema change, source reimport or bulk SKU rename. Draft history uses validated append-only events in the existing shared workspace. Linking and any new inventory counterpart commit together under the same revision check. Existing records preserve identity, inventory/marketplace SKU, source timestamps, costs, prices, location, quantities, status and sales. CDP master SKU is separately stored as a manually confirmed link; existing imported mappings remain unchanged. Drafts are excluded from inventory counts, included in full backups and recoverable across devices. No CDP/marketplace writes or new paid provider.

## Limitations

CDP SKU confirmation is manual; no actual CDP write or live cross-marketplace stock synchronization is implemented. New CDP records must still be created in CDP. Existing record corrections stay in attached intake evidence until edited explicitly. Generic manual Vault entry remains available for non-Vision workflows. Browser automation and physical-iPhone testing are unavailable in this environment; no live-phone acceptance is claimed. Existing eBay CSV upload restriction remains in force.
