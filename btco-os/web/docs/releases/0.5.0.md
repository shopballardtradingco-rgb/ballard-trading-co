# BTCo OS 0.5.0 · Vision source consolidation

## Scope

The OS, recovered iPhone application and Node Vision service now share one repository. The 27 source artifacts are cataloged in `docs/vision-sources.json`; historical files remain immutable in `archive/vision/`. These were file snapshots, not a second Git repository, so this is source consolidation rather than a Git ancestry merge.

The browser Vision module supports photo selection, manual or saved-JSON identity review, current Vault candidate matching, reviewed receipt and a buying worksheet. It uses the same shared save/revision path as Vault. Optional recognition/PSA/active-listing calls use a protected server bridge. Nothing automatically receives, buys, prices or sells a card.

## Data

No database migration. Inventory schema remains version 1. Existing imports, quantities, prices, costs, sales, IDs and snapshots are unchanged by deployment. New reviewed items are quantity one, in Intake, cost unknown and physically unverified. A claimed autograph is not authenticated. Images remain transient; no photo evidence is stored. The blocked October 11 CSV upload is not included or applied through this release.

## Verification

Release gates: `npm test`, `npm run typecheck`, `npm run check:release`, `npm --prefix services/vision-node run check`, and the Sites production build. Tests cover identity mapping, duplicate safeguards, mutation isolation, money rounding, budget/fee/evidence gates, API authentication/origin enforcement, fixed provider paths and service network-access defaults. Existing full-inventory and SQLite-backed storage tests remain release gates.

Pre-build checks passed: all 67 automated tests, TypeScript checking, service syntax and a real local HTTP startup/authentication check with fake provider credentials, plus version markers and the 40 archived source fingerprints. One initial test fixture omitted required sale metadata and was corrected; the release marker check caught a cache-version mismatch, which was also corrected. The production build and final pushed SHA are reported after the release run. The publication operation assigns the hosted version after the commit, so its final mapping is reported to Tim and recorded in `docs/RELEASES.md` at the next release. Never rewrite this file to imply a device or provider test that was not performed.

## Limitations

- Recognition, PSA and active eBay lookup require an independently configured protected HTTPS Vision service and its provider credentials. None is provisioned or charged during this release.
- Active listings are asking prices, never sold evidence. Fee defaults are editable assumptions and may differ from the actual account/category. The browser worksheet currently exposes eBay; the shared calculation module also supports configured CollX/Whatnot channels.
- Native code requires Xcode on a Mac, signing, and physical-iPhone verification. It is preserved and updated here but not compiled or installed from this Linux environment. Native inventory lookup still uses the configured CSV; browser Vision uses the current shared Vault. Native account authentication/shared-Vault access is not yet implemented.
- Browser/Safari visual and camera testing are not available through the supported Sites browser skill in this environment. Automated validation does not establish those checks.
- In-tab scan drafts and worksheet settings are not durable. The browser shows at most eight ranked inventory candidates, so a missing candidate does not prove an item is absent.

## Rollback

Redeploy owner-private hosted version 4 (source `c32cc88ad7f7acd1b393e04edf8f20fa5172abcb`) through the Sites version deployment operation; preserve the shared database and audience. New Vision items use the existing schema and remain valid in 0.4.0. Download a recovery snapshot before any later data repair; code rollback does not roll back records. Revert the 0.5.0 source commit in a new commit if a source rollback is required; never force-push or erase history.
