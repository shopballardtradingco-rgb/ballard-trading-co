# Browser 0.11.1 — restore shared inventory loading

## Scope
Fix a startup regression introduced in 0.11.0. The direct bootstrap seed import was removed, but connectShared still required the retired static initial-inventory/channel-facts JSON files when its per-device migration marker was absent or changed. The failed requests sent the device to an empty or old offline cache even though the saved cloud workspace existed.

## Data
No database schema, inventory, master SKU, physical quantity or sales changes. Read the authenticated shared workspace directly. With no historical baseline available, preserve differing device records as review conflicts and keep the shared record authoritative. Existing explicit new-record merging, device backups, account checks and revision locks remain in place. No production source datasets are reintroduced.

## Verification
Three regression tests exercise the actual browser connectShared module with simulated network/IndexedDB: a fresh empty device, a device containing conflicting local records, and an already-migrated device. The first two fail on 0.11.0 with the reported missing-reference error; all three pass after the fix. Full browser suite, typecheck, source fingerprints and production build are required before publishing. A live read-only status check confirmed 3,886 records at revision 3 and the unchanged prior eBay checksum.

## Limitations
Supported interactive browser QA remains unavailable. Tests cover the actual connection code with synthetic data; the user's device screen requires refresh after publication. Without a historical baseline, local differences may produce more review entries; they cannot silently replace saved cloud records.

## Rollback
Prefer this correction over browser 0.11.0, which contains the known startup failure. If a separate regression requires fallback, private Site version 15 predates that failure. Do not clear device storage, reset the database or re-import historical inventory as a repair.
