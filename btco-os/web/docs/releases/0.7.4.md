# BTCo OS 0.7.4 — PSA hosted connectivity diagnosis

## Scope

Tim confirmed the failed PSA HTTP 403 attempt already used a new API token. Add a bounded hosted network check that developers can run without another user token submission. It requests only `https://api.psacard.com/publicapi/swagger/ui/index`, never a caller-selected address or certificate. Detect an explicit Cloudflare security challenge separately from a generic HTTP 403. Apply the same safe challenge recognition to future PSA connection/lookup errors.

## Data

No migration, inventory change, credential rotation or token retention change. The diagnostic handler has no environment or database bindings and sends no bearer token, cookie or visitor headers. It returns only allowlisted status/classification, a strictly validated Cloudflare Ray reference and timestamp. Response bodies and other headers are discarded. Existing user-record authorization is unchanged; the isolated public-document check uses the existing owner-private Site boundary and supported Site service access. No audience change or automatic retries. Results are coalesced and cached for five minutes per isolate.

## Verification

Test the fixed destination and credential-free request, header/body redaction, explicit versus generic denial, redirects, safe network failures, concurrent request coalescing and cache expiry. All 99 tests passed, including existing provider/Worker/authentication coverage. Release metadata, 40 archived source fingerprints, TypeScript and whitespace checks passed. The production build must complete in the Sites workflow before publication. After deployment, make one authenticated Site service request to the diagnostic endpoint and report the observed result without presenting it as token verification.

References checked October 11: https://www.psacard.com/publicapi/documentation and https://developers.cloudflare.com/cloudflare-challenges/challenge-types/challenge-pages/detect-response/ .

## Limitations

The public-document check tests access from the hosted runtime. It does not prove certificate endpoint behavior, user-token validity or live PSA activation. Provider security/access restrictions require an authorized resolution; this release does not bypass them. No physical-iPhone acceptance test is claimed.
