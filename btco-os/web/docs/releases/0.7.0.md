# BTCo OS 0.7.0 — Secure PSA connection setup

## Scope

Add a private connection form to Vision so Tim can sign in on PSA, paste an API access token directly into BTCo OS and verify it with one real PSA certificate. Save only after an exact certificate record is returned. Invalid tokens, missing records and mismatches preserve the previous connection. Disconnect clears the saved token. The existing scan model, inventory and marketplace behavior are unchanged.

## Data

Append schema-only migration `0002_worthless_hulk.sql` for `vision_credentials`. Each owner has at most one encrypted PSA token, a disconnect marker and timestamps. Encrypt with WebCrypto AES-256-GCM, a random 96-bit IV and owner-bound additional authenticated data. The separate 256-bit wrapping key is the protected Site runtime secret `PSA_CREDENTIAL_KEY`; never put it in Git or client code. Preserve it across deployments. Credentials are excluded from Vault backups, read APIs and scan results; application code does not log credentials. The UI clears the password field on submission and does not use browser storage for the token.

Connection checks share the existing PSA daily allowance and request-ID replay rules. A successful connection atomically saves the encrypted credential, certificate cache and safe operation result. The legacy server `PSA_API_TOKEN` remains supported only when the owner has no overriding saved connection or explicit disconnect. No inventory migrations, marketplace writes or report imports.

## Limitations

The user must sign in on PSA and supply a token plus real certificate in the private form. No live PSA verification is claimed before that action. A successful certificate lookup is not proof of physical slab authenticity. Supported browser QA and physical-iPhone camera acceptance remain unavailable/unverified in this environment. Existing private Sites access and authenticated owner isolation are required. Native iOS compilation/sync and live eBay/CollX integrations remain outside this release.

## Rollback

Redeploy saved Site version 6 (`c0536cfca1d35a6caaec3ed1f702719ad25373a0`) to restore the prior UI. Leave the additive table and wrapping key in place; reverting to 0.6.0 does not read owner-stored PSA credentials and would require the legacy `PSA_API_TOKEN` for lookup. Rolling back code does not alter Vault data. Disconnect in 0.7.0 before removing a saved token. Never rotate the wrapping key as an ordinary rollback step.
