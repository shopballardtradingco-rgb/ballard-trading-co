# Browser 0.11.4 — owner-confirmed comic locations

## Scope

Publication reconciliation optionally accepts a separate owner confirmation of one physical copy and its storage location. The receipt still independently verifies publication. Preview checksums bind both inputs; status returns the current item link, quantity and location.

## Data

New confirmed copies use the connector permanent physical ID, quantity one, exact marketplace SKU and the owner-supplied location. Purchase cost and CDP identity remain unknown. Without confirmation, new receipts retain zero-stock review behavior. Existing records preserve quantities, costs and identifiers; conflicting locations require a separate reviewed move. Signed evidence and owner confirmation are retained separately. Repeated receipts cannot rewrite the confirmation.

## Verification

Domain tests cover explicit physical intake, unchanged existing stock/CDP/costs, location conflicts, duplicate replay and malformed confirmations. Worker/D1 tests cover preview tampering, races, persisted owner evidence and current readback. Release gates: full npm tests, check:release, typecheck and production build.

## Limitations

Owner-private service access remains required. Confirmation of possession is not an interior inspection, acquisition-cost claim or authority to change existing stock. No migration or bulk inventory replacement. Visual browser QA is not part of this API-only change.

## Rollback

Restore the previous source deployment while retaining the existing D1 database and signed events. Never remove published listing links or owner evidence. Prefer a forward correction if a confirmed item needs a later location move.
