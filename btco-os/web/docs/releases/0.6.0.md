# BTCo OS 0.6.0 · Hosted Vision scanning

## Scope

Port recognition from the Mac Node service to the existing OS Worker. Front/back photos are normalized on the phone and sent to the OpenAI Responses API with a strict identity schema. Results are recoverable across devices; inventory changes still require reviewed receipt through the existing shared Vault save path. Known cost and storage location can be entered explicitly. A completed scan cannot be received twice under different SKUs.

PSA lookup is a separate optional provider connection. Cache matching records for seven days, compare the returned certificate exactly, and show official details without overwriting identification or declaring a physical slab authentic. Market lookup still uses the optional legacy service and remains active asking prices only.

## Data

Append schema-only migration `0001_tricky_the_leader.sql` for `vision_operations` and `vision_psa_cache`. Existing Vault tables, source records and inventory schema version 1 are unchanged. No backfill or source-report import. Recognition stores identity JSON, photo hash, model, timestamps, token usage, status and estimated/reserved cost; it does not retain photographs. Original recognition and reviewed edits are separately preserved on a received item.

Default limits are 20 scan attempts, $1.00 estimated/reserved recognition cost, and 90 uncached PSA requests per owner per Pacific day. Each new scan atomically reserves $0.32 against the budget; known usage settles that amount. Failed/uncertain calls retain a conservative reservation when usage is unavailable. Known rejected requests settle to zero estimated cost but remain attempts. Successful repeated request IDs replay results without another provider call. No automatic paid retries. Rates are estimates, excluding tax and account-specific adjustments; provider billing is authoritative.

## Verification

Required gates: all existing inventory/SQLite tests, hosted Vision API tests, TypeScript, release/provenance checks, service startup check, and production build. New tests exercise simultaneous reservations, replay, ambiguous failures, owner isolation, PSA empty/mismatched results, free cache hits at quota, photo dimension limits, duplicate receipts and the complete simulated identification → reviewed receipt → actual Vault commit/read path.

Pre-build validation passed: 79 automated tests, TypeScript, syntax/version/provenance checks, and the real local Node-service startup check. All provider responses used in automated tests are controlled fixtures with fake credentials. These establish application behavior, not real recognition accuracy or a successful live provider connection. Final executed counts, build result, pushed SHA and hosted version are reported at handoff.

## Limitations

- OpenAI and PSA credentials were absent from the hosted environment at the start of this build. OpenAI Developers was installed during this build, but its key-setup skill/tools had not loaded into the active session. Activation requires the supported OpenAI Developers key setup and a PSA API token stored as a protected Site secret. Verify final activation status separately; code publication alone is not a live scan.
- No physical-iPhone camera, HEIC decoding or Safari visual check is available in this environment. Run the acceptance checklist in `docs/VISION-ACCEPTANCE.md` on the actual phone after activation.
- Native iPhone source remains preserved; native shared-Vault authentication and an Xcode/device build remain a later milestone after browser acceptance. Existing native CSV lookup is historical.
- Daily costs are conservative estimates at the documented pinned model rates, not invoice totals. Reservations are intentionally retained after ambiguous failures. Limits are per owner; multi-dealer commercial usage needs tenant-specific provider credentials or a global account budget.
- Images are not retained. Recent results show the latest 20 attempts; original photos must be checked on the device/in hand. Manual/pasted results have no server-verified scan reference.
