# BTCore 0.7.6

When a saved batch finished through BTConnect outside Core, the listing desk kept its cached count. Its resume control could enter the publication path just to update that count. The saved review now has a dedicated **Check eBay status** button. Open Manage listings, continue the saved group, and use that button to read existing outcomes and persist the result. No publication confirmation is requested.

The server calls only `get_listing_batch_review`, fetches all review pages, checks seller/group/draft identities and the saved review revision, and requires complete submitted-group coverage plus verified item IDs before marking the group published. It records a status-check event and time without fabricating Core approval or changing inventory, original photos, shipping, prices, offers, or promotion. Repeated checks are read-only toward eBay. Connection failures leave the previous result intact. Unknown or incomplete outcomes remain visible for their separate recovery workflow.

This closes a direct-operation gap: Core can reconcile work completed by another client without a ChatGPT session. Core still relies on its configured connector and hosting; this release does not claim connector failover, scheduled off-site backups, or Vault receipt reconciliation.

Validation: 122 local service tests passed, one PostgreSQL test skipped locally, and eight promotion tests passed. Focused tests cover external completion, repeated checks, missing/unverified work, mismatched revisions/identities, connection failure and unchanged originals/stock/approval. The browser regression exercises the visible status button, checks for no confirmation and no approval/publish/prepare requests, and reloads persisted completion. Release CI additionally runs PostgreSQL, all browser suites, Docker smoke and portable runtime packaging. Deployment and live acceptance are recorded separately.
