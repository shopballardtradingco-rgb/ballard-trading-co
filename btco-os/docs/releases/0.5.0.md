# BTCore 0.5.0 — Independent CollX prices and listing records

This release adds a CollX workspace to standalone Core. **It does not post to CollX or replace CDP completely.** The required workflow gates and remaining integration work are recorded in [CDP-REPLACEMENT.md](../CDP-REPLACEMENT.md).

## Changes

- Mobile-accessible CollX page with search, attention filter, pagination, original photo downloads and saved card details.
- Separate owner-entered CollX asking prices. Values such as $0.99 and $1.49 retain cents and never inherit, round to, or modify the Core/eBay asking price. Blank means unknown. Identity changes require a CollX price check.
- Owner-recorded CollX listing ID, optional share link, status and price, with server-recorded check time. A target-price edit does not revise the observed listing. Duplicate IDs/links and accidental replacement with a different listing ID are rejected.
- Attention flags for target/observed price differences, reported sold listings, unavailable or held stock, and known eBay publication. These are review reminders, not automated sale detection or delisting.
- Card references survive receipt into the Vault; status observations never create inventory, decrement stock, infer a sale, or create listing approval.
- Authenticated CollX records CSV and existing complete backup retain the new data. The CSV is a Core report, not an accepted CollX upload format. Formula-like text is escaped.
- Workspace revision, per-card fingerprint and operation replay protection prevent stale-device overwrite and duplicate audit events. No new account credentials, infrastructure, database migration or paid dependencies.
- Settings accurately distinguish eBay device connection from CollX posting and automatic delisting; UI version updated.

## Validation

Five new domain/API tests exercise cents, unknowns, target versus observed prices, stale/duplicate rejection, unsafe URLs, stock independence, receiving into inventory, serialization/validation, CSV escaping, authentication/CSRF and operation replay. A mobile browser flow exercises save/reload, status tracking, original-byte download, no external writes and a second-device conflict.

Local verification: 54 tests passed, with the PostgreSQL integration test deferred to CI. Mobile CollX, pricing, preparation and eBay browser flows passed. CI also covers PostgreSQL, other browser acceptance and Docker packaging. All fixtures are synthetic; no live account records or listings are changed by these tests.

## Rollout and limits

Deploy from the verified `release/btcore-development` commit only after its checks pass. This includes 0.4.1 mobile pricing and 0.4.2 pricing safety. Railway build recovery is monitored separately; a source save is not a deployment. Confirm successful deployment commit, `/healthz` version `0.5.0` and `/collx-ui.mjs` before claiming the release is live.

CollX integration/auth access and supported upload contracts remain unconfirmed. Direct posting/repricing/ending, sales sync and automatic delisting are unavailable. No credentials are collected for a speculative adapter. A manual listing check is not API verification. Existing inventory CSV remains backward compatible; CollX targets and observations are in the dedicated CollX CSV and full backup. Receiving into inventory keeps the same channel record. Listing-ID correction and bulk channel edits remain future work; a mismatch must be reconciled rather than overwritten.
