# BTCore 0.6.0 — side-by-side marketplace trial

Tim authorized mirroring live listings beside CDP for several weeks on October 20, 2026. This release copies observations into Core while CDP continues managing existing listings.

## Delivered

- Complete paginated eBay active-listing and order reads through the existing authorized BTConnect account. Reject changing totals, duplicate IDs, bad timestamps, missing pages, wrong seller and unsupported values before commit.
- Exact item, order and line IDs; cent prices; independent observations. Missing listings remain unresolved. Refund/cancellation/payment/fulfillment states are retained without creating sales, decrementing stock or relisting.
- Explicit three-week scheduled trial: 15-minute server checks, encrypted persisted credentials, restart recovery, retry status and stop. Reader allowlist excludes marketplace write tools. First successful read precedes enabling; the connected device must start the trial after deployment.
- Dated CSV mapping and preview for CDP/CollX, independent channel prices, unknown values, exact external-ID joins and stale/incomplete-source warnings. No title/SKU-alias identity guessing.
- Mobile comparison, search, pagination, price/quantity/status exceptions, order exceptions and downloadable history. Existing Core inventory, publication approvals and original photos are untouched.

## Validation

- 63 local tests passed; disposable PostgreSQL acceptance runs in CI (one local skip).
- Mobile mirror flow verifies actual committed snapshot, exact cents, CSV mapping/preview, discrepancies, reload, stop and no stock/credential leakage.
- Existing pricing, preparation, eBay and CollX browser flows are regression gates.
- Captured live eBay baseline was separately validated: 19 pages, 3,629 unique active IDs and 58 orders for October 1–20. Production data is private and is not in this repository. This read does not mean the new Core runtime or scheduled sync is live.

## Deployment / limits

Test this commit on `feature/marketplace-mirror`; advance `release/btcore-development` only after independent-runtime, browser and vault checks succeed at the exact commit. No permanent commit pin. Preserve the already tested 0.5.0 release while CI runs. Railway's October 20 build pause remains a platform gate; inspect deployments before triggering once recovered. Verify deployment SHA, `/healthz` 0.6.0, `/mirror-ui.mjs`, `/collx-ui.mjs` and the comparison route.

The existing development provisioner adds `core_mirror_connection` and grants the runtime role access. No production/BTConnect database changes. Encrypted credentials are deliberately excluded from exports/backups; reconnect after recovery. No new infrastructure or spend setting.

Order reads cover a rolling 30 Pacific calendar days; older-order changes still need separate reconciliation. Latest records, 5,000 changes and 2,000 run summaries are retained (drop count visible); export periodically. Existing workspace size cap remains 12 MB. A failed read keeps the last complete snapshot and reports failure.

Current CDP and CollX exports are still needed for a current comparison. CollX API sync, direct posting, cross-channel delisting, financial reconciliation and live existing-listing edits are NOT delivered. This is the beginning of a measured parallel trial, not complete CDP parity.
