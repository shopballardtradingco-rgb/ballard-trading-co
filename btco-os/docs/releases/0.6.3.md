# BTCore 0.6.3 — Campaign and calculated-shipping repair

The owner hit `get_listing_campaign_snapshot: Invalid campaign ID` in mobile Choose shipping. Core incorrectly treated BTConnect campaign wrapper rows as flat campaign records. Existing browser fixtures also used the wrong shape. The selector now unwraps the real contract, includes only supported running fixed 5% campaigns, and preselects a sole eligible existing campaign. Blank selections are caught before any remote call. The server revalidates the fresh campaign snapshot and rejects a changed rate or unsupported automatic campaign. No campaign, ad rate, selection rule or policy is created or edited.

The seller's existing fulfillment policies are calculated, so the former flat-only guard would have failed next. Core now passes BTConnect's existing measured `packed_parcel` contract. Actual packed weight, length, width and thickness plus an explicit measurement confirmation are required; no measurements are guessed. A saved batch can contain separate shipping settings for raw cards up to $20, raw cards over $20, and graded cards. The latter two cannot select policies containing Standard Envelope. Envelope measurements and owner confirmation enforce the documented size, weight and flexible/uniform paper-envelope limits. Existing flat-rate policies remain supported. Measurements must apply to every card in their group; alternate per-card packaging and reusable shipping profiles remain future work.

Final review displays the exact policy snapshot and measured parcel for each group and each prepared listing. NM is mapped to the returned Near mint or better value, never an invented descriptor ID. Missing required conditions stop before preparation and preserve the saved batch. The existing exact-revision final owner approval, duplicate prevention, original photos, SKUs, prices, physical quantities and independent CollX prices remain unchanged.

Validation: 73 local unit/API tests passed (the separate PostgreSQL test is CI-only). The mobile browser regression uses real-shaped nested campaign wrappers (an ineligible 9% campaign plus the existing automatic 5% campaign), calculated envelope and parcel policies, and a mixed $7/$25 batch. It verifies blank campaign and missing measurements cause no configuration call, higher-value cards cannot select the envelope policy, actual measurements bind to the correct cards, reload retains one saved group, and simulated publication requires final approval. Exact-head independent-runtime (including PostgreSQL, seven browser suites and Docker), browser and vault CI gate promotion.

No real listings are published by this release or its tests. No database migration, new service, policy change, credential extraction or spending change. The owner still needs to provide actual shipping measurements and approve the final live listings. CollX direct posting, sales sync and automatic cross-channel delisting remain unconnected; see `docs/CDP-REPLACEMENT.md`.
