# BTCore 0.6.5 — Selected bulk edits and mobile listing views

## Authorized scope

Tim reported broken phone views, requested a bulk-update selector and conditions matching eBay. This release changes the standalone Core development UI and its validation only. Standing authorization permits a tested development deployment, not real marketplace publication, policy changes or production data migration.

## Changes

- Unpublished editable rows have checkboxes, Select all shown, Clear and Edit selected. Selection can span views; Select all shown is scoped to the current search/filter/page and capped at 500. A compact selected-count action stays reachable on phones.
- Bulk price, condition and shipping fields default to unchanged. Explicit save changes only selected rows, including their pending inline edits. Other pending rows remain untouched. Saved batch identity is retained for staged batches; unapproved prepared previews are replaced for fresh final approval using the existing atomic editor.
- Raw sports/non-sport card choices are Near mint or better, Excellent, Very good and Poor, matching eBay's published card conditions. Arbitrary numeric grades, VG-EX and other legacy assessments are shown as prior assessment notes, never selectable eBay options. They are not silently upgraded or erased. Graded cards and comics retain distinct choices; mixed selections expose only shared valid conditions. API validation rejects unsupported new conditions before any row is changed.
- Shipping lists collapse under a count; conditions collapse per card when complete and expand when a choice is missing. The actual eBay condition descriptors are still fetched for the chosen category. Existing campaign, actual packed measurements, buyer-charge checks and final approval gates remain intact.
- Small-screen dialogs stay within the dynamic viewport, keep a reachable close control and hide the background navigation while open. Single photos are larger; fields and action buttons wrap without page overflow. Listing-batch actions appear above the card list.
- Raw singles through $20 retain shared PWE routing and the owner's $0.78 label baseline, not an invented current rate or buyer shipping charge. More expensive singles, graded cards, lots and comics do not inherit PWE.

## Verification and release gate

- Unit/API regressions exercise canonical conditions, legacy preservation, mixed types, atomic invalid-condition rejection, stale fingerprints, stock locks, auth and idempotency.
- New synthetic browser suite covers selected-only bulk edits, filtered select-all, independent pending edits, stale revision rejection, received stock preservation, mixed condition choices and dialogs at 320×568, 390×664 and 844×390.
- Eight browser suites, all unit/API tests, disposable PostgreSQL and Docker smoke are required. Browser tests use Chromium; native iPhone/Safari owner acceptance remains outstanding.
- Deploy only after exact-candidate independent-runtime, browser and vault checks succeed. Verify Railway SUCCESS and exact SHA, /healthz 0.6.5 and matching UI assets. No real listing is published by acceptance tests.

eBay official condition guidance checked 2026-10-21: https://pages.ebay.com/cardconditions/ and https://www.ebay.com/sellercenter/selling/what-to-sell/selling-trading-cards .
