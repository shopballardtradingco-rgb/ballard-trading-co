# BTCore 0.7.4 — eBay publisher progress repair

Core's inline publisher continued only when the verified count increased. BTConnect legitimately records a rejected card without increasing that count, then makes the next unattempted card eligible. Core stopped at that boundary, stranding the remaining approved selection. The older modal also made an extra call before checking progress. Both paths now follow an explicit server continuation result based on durable publication/attempt changes.

The server skips owner-action entries and future retry times before asking the connector to work. It never rearms an uncertain write, changes an approved review or creates a replacement offer. An unchanged response stops automatic continuation. A failed card stays in the original batch with its actual error; successful cards retain their verified item links. No schema or paid dependency changed.

## Evidence and limits

- Regression cases cover a rejected first card followed by a valid card, future retry times, unchanged replies, repeated calls and exact approval.
- The mobile browser acceptance covers one confirmation, a failed first card, a successful second card, visible error details and reload/resume without retrying the blocked card.
- All 24 saved Core drafts passed the actual BTConnect 0.6.0 card model during a private offline check with synthetic policy/photo references. This verifies serialization only, not live policy eligibility or publication. No private card data was added to tests or source.
- Read-only checks found BTConnect 0.6.0 responding with listing permissions and Core still serving 0.7.2. The two active saved Core batches had not reached connector configuration. This repair is a reproduced queue bug, not a claim that the precise cause of those staged batches has been proven.
- Existing Core unit, PostgreSQL, mobile browser and Docker gates must pass on the reviewed commit. Railway control-plane access is unavailable; a source release is not deployment proof. Confirm health and asset identity before claiming the fix is live.

Implementation permission is not approval to publish the owner's cards. No live eBay listing was created, edited or retried. A separately approved exact card review and its verified eBay item ID remain the final live acceptance gate.

## Rollout

This release builds on 0.7.3 and retains its location/fulfillment code; no migration is automatically applied. Use the existing development release branch only after its required checks pass. Preserve the forward-only stock-ledger compatibility constraints in 0.7.3. Do not add unrelated features while the live publisher acceptance remains open.
