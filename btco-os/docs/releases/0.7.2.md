# BTCore 0.7.2 — Performance and independence maintenance

This pass adds no product features. Reduce redundant CPU, database work and object-storage transfers while preserving the existing CDP-free eBay path and manual operation without ChatGPT or AI.

- Gzip static assets once per process; content-hash revalidation avoids repeat downloads and still refreshes changed releases.
- Revalidate authenticated previews before reading blobs/S3. Read only the requested database derivative; preserve original integrity verification and private API `no-store` behavior.
- Idle preparation checks revisions without locking/parsing the whole workspace. External changes and expired leases still wake it. No repeat paid calls or change to spending reservations.
- Skip hidden-tab and overlapping browser preparation polls, and protect edits from a delayed poll redraw.
- Record actual paid dependencies and owner priority in [the dependency audit](../DEPENDENCY-AUDIT.md): CDP first, ChatGPT second; other markets remain secondary and part of the eventual strategy. Existing prices, identifiers, channel contracts and provenance are retained.

No schema migration, package additions, provider change or marketplace writes. Existing Core 0.7.1 data/backups remain compatible. Rollback requires no data conversion.

Validation: focused HTTP tests compare compressed and original bytes, encoding negotiation, conditional requests, private owner checks, object-read counts, database blob selection, logout and corrupt-original rejection. Worker regression verifies idle lock avoidance, revision wake-up and lease expiry. Full unit tests and existing mobile preparation/direct-eBay flows are required; exact-commit PostgreSQL, browser, utility and Docker CI must pass before development promotion. These synthetic checks are not a live eBay publication pilot or proof that CDP can be cancelled.
