# BTCore 0.7.3 — CDP location migration

The comparison importer previously discarded physical locations and did not populate Core inventory. This release adds the authorized migration and fulfillment path without another service or subscription.

## Data contract

| CDP field | Core field | Treatment |
| --- | --- | --- |
| ID | source.cdpId | Exact string; independent from marketplace identifiers |
| SKU | sku and source.cdpSku | Exact master SKU; locked against accidental edits |
| Cabinet | physicalLocation.office | Original spelling retained |
| Shelf | physicalLocation.shelf | Extra level retained, including leading zeros |
| Box / Row / Section | physicalLocation.box / row / section | Original strings retained |
| Full source row | cdpMigration.raw | Includes costs, notes, dates and extra columns unchanged |
| Purchase Price | source.cdpPurchasePriceReported and original row | Source evidence, not a replacement of reviewed allocated cost |

Display: Office → Box → Row → Section, with Shelf and extra detail alongside. CollX's five-part location string is Cabinet / Shelf / Box / Row / Section. Other free-text paths remain unstructured; no positional guessing.

Migration fills a new record from its source row or adds missing metadata to an exact existing identity. Existing SKU, cost, quantity, status and nonblank location are preserved. Conflicting IDs or locations generate exceptions. Zero-quantity historical rows remain unavailable review records. Source quantity is a dated baseline, not physical verification. Import preview is read-only and commit is revision-checked and idempotent.

## Lookup and fulfillment

- GET `/api/inventory/lookup?channel=collx&kind=sku&value=...`, or `?query=...`; multiple matches return an explicit ambiguity.
- GET `/api/inventory/locations` returns complete missing, partial, conflict and duplicate-identifier reports.
- POST `/api/inventory/import/preview` and `/api/inventory/import/cdp` accept original CDP rows plus observedAt. An optional observedAtBasis documents conservative timestamp provenance.
- POST `/api/inventory/link` requires an exact item, channel, identifier kind/value and evidence. It never rewrites the master SKU.
- eBay links use both exact source master SKU and exact title with unique agreement. Prefixes, alias SKUs and title-only matches do not link inventory.
- GET `/api/fulfillment` resolves each recorded order line. Existing eBay sync applies only paid, uncancelled, uniquely linked orders newer than the stock baseline. Stable order/line keys prevent replay. Partial quantities are supported; insufficient stock is flagged.
- POST `/api/fulfillment/record` accepts an owner-confirmed sale for an unconnected marketplace. An internal owner sale reference is explicitly labeled when the actual marketplace order ID is unavailable. It is not an API sync claim.
- Missing/conflicting locations remain explicit even when a confirmed sale reduces available stock. Cross-channel closure remains manual and is shown as required work.
- Financial amounts are not invented from order status. The existing sale form can reconcile one exact allocation by matching item, channel, reference and quantity. Financial reversal does not restock a still-confirmed marketplace sale. Multi-line financial reconciliation remains manual review.

## Verification and rollout

Synthetic tests cover source preservation, duplicate/conflicting identities, blank marketplace fields, lookups across linked namespaces, replay, stock protection, historical/cancelled orders, oversell prevention and finance allocation. Mobile browser coverage exercises migration preview, import, location display, audit and search. CI also runs the existing PostgreSQL, browser and container gates.

Actual inventory exports were used only in a private local dry run, against a copy of the live workspace. They are never test fixtures or public repository data. Live migration is a separate, backed-up, revision-checked operation. Record its counts and source timestamps privately; a passing CI run alone does not prove synchronization complete.

Rollback: keep the pre-import workspace backup. Do not run older code against a workspace containing marketplaceAllocations: older versions do not deduct that ledger. Prefer a forward fix; never restore over live data without separate owner approval and reconciliation of sales since the backup. Marketplace listings and credentials are unchanged by the migration.

Local validation: 114 Core tests passed (one PostgreSQL-only skip), 39 directly affected legacy inventory tests passed, and 10 Python tests passed. The first new mobile test exposed heading overflow; the scoped responsive fix is covered by the same test. PostgreSQL, all existing browser suites, legacy typecheck/build and the container run are required in CI before promotion.
