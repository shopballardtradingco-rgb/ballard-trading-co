# Connector 0.3.3 — measured shipping and publication readiness

The comic fulfillment policies use calculated shipping. Earlier connector versions rejected that mode because the draft contract had no package measurements. This release carries actual packed measurements through review, publication, and read-back verification.

## Draft contract

`packed_parcel` remains optional for flat shipping. A calculated service requires all of:

- `weight_oz`, `length_in`, `width_in`, `height_in`: positive decimal strings, up to three fractional digits. Maximum supported inputs are 1,120 ounces and 120 inches per dimension; these are input bounds, not carrier eligibility guarantees.
- `verified: true`, with `evidence` describing the actual packed measurements and their source.

There are no measurements inferred from a brand, mailer name, photograph, or a synthetic test fixture. The supported package is a regular parcel (`PACKAGE_THICK_ENVELOPE`, `shippingIrregular: false`). eBay receives numeric measurements with explicit `OUNCE` and `INCH` units. Read-back compares physical measurements with exact decimal unit conversions, including normalization from ounces to pounds. Missing or changed package data stops verification, and retries retain the existing offer.

All package fields and evidence enter the revision hash. Changing them invalidates approval. Old serialized revisions must be re-saved and reviewed under the current contract; they cannot silently gain shipping data.

## Condition and promotion checks

Inventory API used-condition codes are `USED_EXCELLENT`, `USED_VERY_GOOD`, `USED_GOOD`, and `USED_ACCEPTABLE`, not the display labels previously used by the connector. These codes do not assign a numerical comic grade. `LIKE_NEW` remains available only where supported and justified by actual evidence. Live category metadata must support the selected condition; conditions needing a separate descriptor/eligibility workflow are rejected. Best Offer requires verified auto-decline support in the selected category.

`get_listing_policy_options` now also reads category 259104 condition/Best Offer metadata and existing running CPS campaigns. Optional discovery failures are returned explicitly without concealing business-policy results. The publication preflight reads the actual selected category again and fails closed on errors.

Campaign discovery checks complete, stable totals, unique IDs, offsets and page bounds; it never follows remote pagination URLs. Only existing running US onsite manual campaigns with fixed CPS rates qualify. No campaign, budget, policy, account permission or live inventory is changed by discovery. A missing eligible campaign is not proof that promotion is unsupported; it remains an unresolved setup requirement.

## Verification

175 tests pass with synthetic images, synthetic parcel measurements, and simulated eBay responses. Coverage includes approval invalidation, unit normalization, package drift after publication, recovery without duplicate writes, calculated-policy requirements, category eligibility, campaign pagination, and authenticated read-only readiness. Health and connection status both report 0.3.3.

The pilot's original images have previously been ingested privately. Owner authorization to publish does not supply missing printing/interior evidence or actual packed measurements. No pilot listings have been published by this release, and the deployment publication switch remains disabled until those factual requirements and complete reviewed drafts are satisfied. Production images, object references, credentials, seller-specific draft data and measurement evidence are excluded from this repository.
