# 0.3.13 — Recover a rejected saved offer

Blackmoon #2 reached an eBay offer, then eBay rejected publication with HTTP 400
and code 25604. The old journal retained only a generic error string, which later
read-back attempts replaced. Ordinary retries correctly avoided another write,
but there was no reviewed path to recover the existing unpublished offer.

## Recovery

The existing `approve_listing_draft` tool can now record explicit owner recovery
approval for that same saved revision and offer. This performs no eBay writes.
It requires a five-minute quiet period, original checksums and uploaded-image
bindings, unchanged inventory and offer content, existing policies and campaign,
a complete duplicate scan, and two authoritative reads showing exactly one
UNPUBLISHED offer with no listing ID. Seller, draft revision and offer identity
are bound into a durable, fifteen-minute authorization.

The subsequent `publish_approved_listing` call repeats all existing preflight
checks and consumes that authorization before one request to the same offer.
It never creates a replacement offer, clears `publish_attempted`, overwrites
inventory, changes the approved revision, or implicitly retries HTTP writes.
A timeout, malformed response, changed content, active duplicate, stale approval
or consumed authorization remains blocked. Already published offers use the
existing read-back path instead.

New publication failures preserve HTTP status, numeric codes, uncertainty and
allowlisted reason labels in the journal, separately from later guard errors.
Arbitrary provider messages and parameters remain excluded. New uncertain
failures cannot be rearmed. Older jobs without typed failure journals require
explicit owner recovery approval and the same fresh state checks; they are never
automatically interpreted as definite rejections.

## Validation

26 new recovery tests cover the legacy and typed-rejection paths, immutable
content, same-offer reuse, duplicate/policy/inventory/photo checks, stale and
cross-seller authorization, expiry, one-use consumption, racing offer changes,
timeouts, diagnostic redaction and the existing MCP approval route.
The complete suite passes: 346 tests, with two existing framework deprecation warnings.

No schema migration, credential change, new tool name, replacement volume or
new eBay permission is required. Deploy through the existing GitHub-to-Railway
pipeline. Verify the exact Blackmoon offer and live item after deployment;
passing synthetic tests alone does not prove publication.
