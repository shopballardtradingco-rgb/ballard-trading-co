# Connect 0.4.0 — Chat batch reliability

Status: development release candidate; **not deployed**.

The prior connector required Chat to retain individual IDs and orchestrate
recovery manually. Its disclosure contract also omitted a sentence enforced
by the validator. This release makes the exact requirements discoverable and
puts batch state, review and continuation into Connect's persistent store.

Changes:

- Complete disclosure contract plus preparation-only disclosure additions.
- Private stored-photo catalog/view and legacy saved-draft discovery.
- Durable batches with physical location, original pairs and isolated exceptions.
- Full paginated review; one atomic approval bound to exact revisions and policy.
- Bounded publication/resume, image retry handling, same-offer reconciliation and
  an optional explicitly reviewed one-retry policy for confirmed rejections.
- Compact results with verified IDs, promotion status and unresolved work.

No changes to Core, production credentials, deployed services or live listings.
Existing single-listing tools and historical draft hashes remain compatible.

Validation: 375 local tests passed on Python 3.12, including all 346 existing
tests and 29 new batch/catalog/approval/recovery tests. Two pre-existing
Starlette/AnyIO deprecation warnings remain. No live inventory was used.

Regular Chat tool discovery and a separately owner-approved live pilot remain
unverified until release. See [workflow and release gates](../CONNECT-CHAT-BATCHES.md).
