# Connector 0.3.6 — conditionless inventory read-back

The first approved pilot attempt uploaded both original photographs and created its eBay inventory item. eBay returned the exact main description, images, quantity and parcel, but omitted `conditionDescription` because no condition code was selected. The verification gate correctly stopped before offer creation or publication; no live listing was created by that attempt.

For a draft with `condition: null`, the Inventory API payload now omits the standalone `conditionDescription`. The approved main product and offer descriptions remain exact, including exterior wear and the uninspected-interior disclosure. An unexpected condition code or condition description still fails read-back. Drafts with a specified condition continue to send and verify their standalone description. No saved draft field or revision hash changes in this fix.

`get_listing_draft` now reports live inventory read-back for an existing saved publication job, and offer read-back when its saved offer ID exists. These are seller-scoped GET requests bound to the saved SKU/offer, with no arbitrary identifier input and no remote mutation. The diagnostic response never replaces the approved draft or writes observed data into approval records.

The same durable job, original hosted photographs and inventory SKU are reused on recovery. Existing approval remains required and duplicate guards remain active. The fix does not grant approval, alter prices or offer floors, claim an interior inspection, or recreate an unresolved inventory item.

215 tests pass. Regression coverage includes API-added inventory metadata, omission of the standalone condition description, preservation of the complete main description, rejection of missing interior disclosure on read-back, and diagnostics that cannot mutate saved approval or eBay. Production publication is enabled only after the owner's explicit approval of all five complete pilot revisions; actual publication and reconciliation are verified separately.
