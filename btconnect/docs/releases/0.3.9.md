# 0.3.9 — Original-photo transfer and publication outcomes

## Changes

- `ingest_original_photo` accepts the native ChatGPT file input contract (`openai/fileParams`). It downloads only HTTPS files from supported OpenAI download hosts, never follows redirects, sends no seller credentials, bounds time and bytes, and suppresses signed-URL logs. The existing encrypted PhotoStore verifies the supplied original SHA-256 and image integrity. Durable bytes are read back before success. Repeats preserve the same object identity.
- `scripts/upload_original.py` uses curl's configured network connection for the existing one-use raw upload route. It accepts a ticket on hidden stdin, never puts tokens in files or process arguments, does not retry or follow redirects, and validates the returned checksum and photo role.
- `get_listing_contract` returns the actual nested schema. `save_listing_draft` now advertises `ListingDraft` rather than an opaque dictionary. `validate_listing_draft` reports field paths without echoing private input and verifies stored originals without saving or approving.
- New review drafts require Best Offer with an explicit minimum, Good/Acceptable, a measured or authorized estimated packed parcel, and explicit unverified page-quality/hidden-defect/extra disclosures for exterior-only inspection. The historical model and revision hashing are unchanged; no old approval is silently rewritten.
- Publication tool failures return durable stage, saved offer, known item ID/URL, verification status and recovery instruction. A live listing awaiting promotion verification is distinguished from an unknown publish outcome.
- Automatic campaign verification reads active ads using the exact published listing ID. The prior inventory-reference lookup returned HTTP 409/error 35064 in the historical pilot. No campaign settings or ads are changed by this read.
- Verified journal and receipt-source writes commit in one database transaction. Recovery error recording reloads durable state after a transaction failure.

## Verification

Baseline: 238 tests. Updated: 278 synthetic tests on Python 3.12, including file schema, original-byte preservation, seller permission, revoked grants, restricted download destinations, size bounds, redacted errors, draft validation, automatic-campaign lookup, ambiguous outcomes and transaction rollback. Existing two upstream test-framework deprecation warnings remain.

Live photo transfer on October 13: a previously ingested original JPEG (847,590 bytes) was transferred using the raw upload helper and returned the exact existing checksum, seller-bound object key and front role. This was a storage-only idempotence test, not a new listing test. No photographs were regenerated, no draft approved and no marketplace write performed.

Native host file injection still requires live acceptance with a fresh user file and refreshed tool discovery. The raw route is available independently of that refresh. Production deployment and promotion read-back results must be recorded after release; a passing synthetic suite alone does not establish either.
