# BTConnect 0.6.0 — card batches and standalone Core authorization

Adds a separate CardListingDraft while retaining historical comic serialization and approvals. Card batches accept one original front, exact master SKU, current graded/ungraded descriptors, existing policies and promotion snapshots. The same reservation and publication journal handles both products. Descriptor read-back is part of inventory verification; condition metadata is checked per descriptor selection. Graded cards or cards above $20 cannot use an eBay Standard Envelope policy.

The new get_card_listing_options tool returns card schema, current condition metadata and existing seller options. Existing batch preparation/review/approval/publication tools handle cards. Current comic tools and their stricter two-photo/inspection rules remain intact.

An optional exact HTTPS BTCORE_CALLBACK_URL permits Core's OAuth PKCE flow; all other non-ChatGPT callbacks stay blocked. Existing ChatGPT clients and grants are untouched. No new listing is authorized by deployment.

Validation includes front-only and graded contracts, exact SKU preservation, changed descriptors, lost write responses, mixed-card batches, no duplicate publication, envelope exclusions, exact callback allowlist and the full connector regression suite. Actual marketplace acceptance still needs an owner-approved live pilot.

API references: https://developer.ebay.com/api-docs/sell/inventory/resources/inventory_item/methods/getInventoryItem and https://developer.ebay.com/api-docs/sell/metadata/resources/marketplace/methods/getItemConditionPolicies .
