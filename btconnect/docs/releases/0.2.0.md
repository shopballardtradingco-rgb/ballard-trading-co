# 0.2.0: Active eBay listings

Release date: 2026-10-11 Pacific / 2026-10-12 UTC.

## Behavior

The existing private connector gains `get_active_listings(page)` for the authorized seller. It reads the Trading API's active-listing view, including listings created through CDP, and returns at most 200 records per page. Only the fixed GetMyeBaySelling operation can be sent; no listing or order mutations are exposed. CDP remains the listing hub.

Records include eBay item ID, listing SKU, title, listing format, price/currency, quantity evidence and variations. Unknown values remain null. Private notes and buyer details are excluded. Response size, XML declarations, redirects, HTTP failures, warning/partial acknowledgements, pagination mismatch, duplicates within a page and the 25,000-item limit fail closed.

Page reads are not an atomic snapshot. The caller must check all page counts and cross-page duplicates, preserve CDP SKU mappings and physical stock, and never turn absence into a sale/deletion. Multi-variation listings need review before any item-level import.

## Authorization and migration

New eBay consent includes the standard Trading scope. Existing grants continue refreshing their original permissions; the status tool identifies when reconnection is required. Reconnect the existing BTCo eBay plugin to approve listing reads. Existing seller restriction, MCP audience, credentials, Railway volume and database remain in place. There is no database migration.

## Verification

48 tests passed against synthetic providers using Python 3.12 and the pinned runtime dependencies. Coverage includes existing OAuth/PKCE/revocation boundaries plus inventory transport, pagination, variation/unknown quantities, sanitized failures, redirects, XML declarations and legacy scope refresh. Two existing upstream test-framework deprecation warnings remain.

The production build/deployment must be verified by Railway's terminal SUCCESS and the live version/status response. A local test cannot establish live eBay permission. At source commit time, live active-listing consent/readback, the BTCo OS writer and daily scheduling have not yet been verified. No automation is created by this release.

## Rollback

Roll back Railway to the previous successful deployment or restore source commit `5c04dab79ed3e819ba0090957850b017356c144c`. Keep the persistent volume and TOKEN_ENCRYPTION_KEY. Added grant metadata is backward compatible; source rollback does not revoke any broader eBay permission already consented. Revoke/reconnect through the supported OAuth flow if revocation is desired.
